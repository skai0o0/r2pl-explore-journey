# V1 audit and V2 reuse decisions

Audit basis: local read-only clone `land-rush-prototype` at commit `79e5cfa2a16101fd3872eacb52ef6d2fafcc03d4`, inspected 2026-10-09. Decisions are candidate-level: **PORT** extracts a tested algorithm, **REDESIGN** preserves behavior with new ownership/contracts, **REBUILD** writes fresh against V2 contracts, **DISCARD** removes legacy behavior. No V1 file is a V2 source file.

## Architectural findings

- V1 already avoids a million **Colyseus Schema** tile objects, but the client eagerly allocates a million render instances. These are different costs.
- `CampusRoom` has many unrelated responsibilities and duplicate old/new land channels. A clean V2 gateway/service split is warranted.
- V1 sends `world_delta` with room-wide broadcast and sends all touched chunks on join. School fog is filtered, but raw school masks and some shared knowledge metadata remain broadly visible. V2 needs an explicit visibility policy and subscriptions.
- V1 world persistence batches asynchronously after gameplay acknowledgements. Wallets, rewards, chests and landmark progress remain transient. V2 cannot inherit its durability semantics.
- V1 has meaningful tests and binary microbenchmarks, but the real WebSocket test uses an in-memory repository; the PostgreSQL restart acceptance script is opt-in. The repository does not demonstrate V2 concurrency, 10k connections or crash-safe rewards.
